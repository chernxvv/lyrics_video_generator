# Lyrics Video Generator

Desktop GUI-приложение (PySide6) для генерации lyric-video по аудиотреку.

## Что поддерживается сейчас

- Две ориентации видео: `9:16` (vertical) и `16:9` (horizontal).
- Два render-режима для каждой ориентации:
  - Vertical Preview: `540x960`, `24 fps`.
  - Vertical Final: `1080x1920`, `30 fps`.
  - Horizontal Preview: `960x540`, `24 fps`.
  - Horizontal Final: `1920x1080`, `30 fps`.
- Два режима синхронизации текста:
  - **Ручной** (таблица `мм:сс + строка`).
  - **Автоматический** (анализ аудио + полный текст трека, затем автозаполнение таблицы с ручной правкой).
- Два режима фона:
  - `Мягкий градиент` (базовый MVP-режим).
  - `Динамический BPM-фон` (реакция на beat, мягкие размытые вспышки по палитре).
- NVENC с автоматическим fallback на `libx264`.
- Streaming/chunked render (многопоточная генерация кадров и pipe в ffmpeg).

## Структура

- `gui/main_window.py` — GUI: ориентация, режим синхронизации, авто-синхронизация, режим фона.
- `models/project.py` — модели проекта + render profiles.
- `core/audio.py` — чтение длительности через `ffprobe`.
- `core/image_analysis.py` — извлечение палитры из обложки.
- `core/layout.py` — адаптивная геометрия композиции кадра (`vertical`/`horizontal`).
- `core/lyrics.py` — парсинг/сортировка таймингов, активная строка.
- `core/auto_sync.py` — baseline авто-синхронизация lyrics.
- `core/audio_analysis.py` — BPM/beat-анализ (Demucs 6-stem + fallback), сбор единой событийной линии вспышек.
- `core/background.py` — стратегии фона (`soft_gradient`, `bpm_dynamic`).
- `core/validation.py` — валидация проекта.
- `core/render.py` — streaming-рендер и muxing через `ffmpeg`.

## Установка

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Также в системе должны быть установлены `ffmpeg` и `ffprobe`.

### Если на Windows ошибка `WinError 2`

Это почти всегда означает, что не найден `ffmpeg` или `ffprobe` в `PATH`.
Установите FFmpeg и добавьте путь к бинарникам (`ffmpeg.exe`, `ffprobe.exe`) в системную переменную `PATH`.

## Запуск

```bash
python main.py
```

### Примечание по установке pip и deprecation warnings

Сообщения вида:
- `DEPRECATION: ... using the legacy setup.py install method`

обычно **не блокируют работу приложения прямо сейчас**, но означают, что часть зависимостей устанавливается старым способом и в будущих версиях pip поведение может измениться.

Что делать безопасно:
- обновить `pip`, `setuptools`, `wheel`;
- при необходимости установить с `--use-pep517`;
- если установка прошла успешно и приложение запускается, это warning, а не runtime-ошибка рендера.

## Режимы рендера

Перед генерацией выберите режим:

- **Preview** — черновой рендер для быстрых проверок.
- **Final** — финальный экспорт.

Итоговые разрешения зависят от выбранной ориентации:

- **Vertical (9:16)**
  - Preview: `540x960`, `24 fps`
  - Final: `1080x1920`, `30 fps`
- **Horizontal (16:9)**
  - Preview: `960x540`, `24 fps`
  - Final: `1920x1080`, `30 fps`

Также в GUI есть модалка **«Настройки производительности»**, где можно задать:
- `Количество потоков` для генерации кадров;
- `Размер чанка` (по умолчанию 60 кадров).

## GPU-кодирование (NVENC) и fallback

По умолчанию рендер пытается использовать аппаратный кодек `h264_nvenc`.
Если NVENC недоступен, автоматически включается программный fallback `libx264`.

Важно: в текущей архитектуре GPU ускоряет **кодирование** (NVENC), а генерация кадров (фон + текст + компоновка) выполняется на CPU. Поэтому низкая загрузка GPU при медленном рендере обычно означает CPU-bound участок.

Выбор кодека, причина выбора и фактическая скорость рендера (fps) логируются в процессе рендера.

### Проверка доступности NVENC

```bash
ffmpeg -hide_banner -encoders | rg h264_nvenc
```

Если строка найдена — NVENC доступен из текущей сборки ffmpeg.

### Filtergraph и CUDA-preprocess

В `filter_complex` есть две разные ветки подготовки обложки:
- **CPU-ветка:** `scale + crop`.
- **CUDA-ветка:** `format=nv12 -> hwupload_cuda -> scale_cuda -> hwdownload -> format=nv12 -> crop`.

Как выбирается ветка:
1. Проверяется доступность NVENC и CUDA-фильтров (`scale_cuda`, `hwupload_cuda`).
2. Выполняется короткий runtime-probe CUDA на реальном ffmpeg.
3. В логах явно фиксируется выбор (`CUDA filtergraph: enabled/disabled`) и сама ветка (`CPU` или `CUDA`).

Если CUDA-ветка падает во время рендера (runtime-сбой драйвера/устройства/ffmpeg), рендер автоматически перезапускается с CPU-веткой. Причина отката логируется.

### Что гарантированно ускоряется, а что остаётся CPU-bound

**Гарантированно ускоряется (при доступных NVENC/CUDA):**
- Кодирование видео через `h264_nvenc`.
- Масштабирование обложки в CUDA-ветке `filter_complex`.

**Остаётся CPU-bound в текущей архитектуре:**
- Генерация фона (включая BPM-динамику).
- Подготовка lyric-overlay в Pillow.
- Компоновка кадров в Python перед отправкой в ffmpeg pipe.

## Режимы синхронизации

### Ручная синхронизация

- Ввод строк и времени старта вручную в таблице `мм:сс`.
- Полностью совместима с текущим MVP-процессом.

### Автоматическая синхронизация

- Выберите режим **«Автоматическая»** в GUI.
- Вставьте полный текст трека (или загрузите текст из файла).
- Нажмите **«Синхронизировать автоматически»**.
- Таблица строк будет автоматически заполнена и останется доступной для ручной правки.
- По умолчанию используется **WhisperX forced alignment**: входной текст трека выравнивается по аудио (без повторного STT текста).
- Если WhisperX недоступен или alignment не удался, включается fallback на **донастроенный librosa backend** (onset/energy с улучшенными параметрами).


### Примечание по WhisperX

При первом запуске WhisperX может потребоваться загрузка моделей/компонентов, поэтому первый анализ может быть заметно дольше.
Если backend недоступен в окружении, приложение автоматически переключается на librosa fallback.

### Примечание по Demucs

Для более точного BPM-реактивного фона анализ сначала пытается использовать Demucs (`htdemucs_6s`) и выделить stem-ы (`drums`, `bass`, `guitar`, `piano`, `other`, `vocals`).
Далее формируется единая событийная линия вспышек (winner-take-all по stem-источнику) с quality-фильтром и паузами.
Если Demucs недоступен, автоматически применяется fallback на HPSS-подход в librosa.
Первый запуск Demucs также может быть медленнее из-за загрузки модели.

## Режимы фона

- **Мягкий градиент** — классический плавный анимированный фон по палитре обложки.
- **Динамический BPM-фон** — базовый слой от доминирующего цвета + "heartbeat"-события из multi-stem анализа: интенсивность/хаотичность учитывают stem-источник, локальный темп, перкуссионную энергию и (опционально) вклад вокала; между событиями сохраняются паузы.

## Ограничения и ожидания качества

### Авто-синхронизация

- Это **usable baseline**, а не идеальный forced alignment.
- WhisperX forced alignment обычно даёт более точные точки старта строк при известном тексте, но тоже не гарантирует идеал.
- Лучше всего работает на треках с различимым вокалом.
- При плотной обработке вокала, шумном миксе, экстремальных вокальных техниках точность снижается.
- После автоанализа таблица остаётся редактируемой (рекомендуется ручная доводка).

### BPM-анализ и динамический фон

- Beat detection выполняется один раз перед рендером.
- Для модуляции эффекта используются не только beat-события, но и локальный темп/перкуссионная энергия (если доступны из анализа).
- При наличии Demucs строится единая событийная битмап-линия по stem-ам (`drums/guitar/piano/other`) без "скрещивания" источников в одном событии.
- Вокал используется как дополнительная модуляция только в участках, где вокальный stem действительно активен.
- При слабом результате анализатора применяется fallback-поведение (в логах есть предупреждения).
- Эффект сделан мягким и атмосферным (без агрессивного строба), но сложность сцены всё равно может замедлить рендер.

## Что влияет на скорость рендера

- Разрешение и FPS (Final тяжелее, чем Preview; 16:9 Final также ресурсоёмкий).
- Доступность NVENC и выбранный видеокодек/пресет (`nvenc_preset`, `nvenc_cq`).
- Режим фона (`bpm_dynamic` может быть тяжелее `soft_gradient`).
- Производительность CPU/GPU и скорость дисковой подсистемы.
- Количество изменений активной строки (перерисовка текста происходит только при смене активной линии).
- Параметры многопоточности: слишком большой чанк увеличивает пиковую память, слишком маленький — повышает накладные расходы. Для снижения пиков CPU попробуйте `threads=1` или меньший `chunk`.

## Бенчмарк (пример: 60 секунд трека)

Сравнение стоит проводить на одной и той же машине/сцене:

| Сценарий | Режим | Кодек | Время рендера |
|---|---|---|---|
| Базовый | Vertical Final | libx264 | _измерьте локально_ |
| С новыми режимами | Horizontal Preview | h264_nvenc/libx264 | _измерьте локально_ |
| С новыми режимами | Horizontal Final + bpm_dynamic | h264_nvenc/libx264 | _измерьте локально_ |

Минимальный шаблон команды проверки синтаксиса:

```bash
python -m compileall .
```

## Как пользоваться

1. Выберите аудиофайл.
2. Выберите изображение обложки.
3. Заполните метаданные (исполнитель, название, дата).
4. Выберите режим синхронизации:
   - ручной — заполните таблицу `мм:сс + строка`;
   - автоматический — вставьте текст, запустите авто-синхронизацию и при необходимости скорректируйте таблицу.
5. Выберите ориентацию видео и режим фона.
6. Выберите режим рендера (Preview/Final).
7. Нажмите «Сгенерировать видео» и выберите путь сохранения.
